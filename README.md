## 第一条体验路径：放下手机跟练

运动 → 动作库 → 原地踏步（或扶椅提踵）→ 播放示范 → 自行设置组数/次数 → 加入今天并开始 → 设置每组时间与休息 → 5 秒准备后开始跟练。

自动经过准备、练习、休息、下一组；计时结束后一次核对实际完成。暂停训练/跟练会同时冻结总计时与跟练倒计时；离开训练页、刷新或浏览器发出后台事件时保存暂停状态，回来后手动继续。动作示范自身的暂停/重播不改训练计时或已完成组数。多动作安排从“运动 → 今日训练 → 安排自己的训练”创建。训练时保持网页前台；不保证系统强制终止时能收到保存事件。可选本机中文语音，浏览器没有本机中文声音时明确提示，不调用云语音。

已交付 **15 个真实连续 MP4、18 个动作条目**。在原有原地踏步、徒手浅蹲、臀桥、鸟狗式、扶椅提踵基础上，新增站姿猫牛式、侧步并脚拍手、死虫式、仰卧滑跟、四点支撑猫牛式、站姿交替抬膝、轻柔后踢腿、徒手髋铰链、肩部向后绕环、手臂小幅绕环。所有循环保持上游原节奏。列表只加载封面，详情按需加载当前视频。坐站练习、靠墙俯卧撑、扶椅浅蹲保留 NHS 图文入口，未用相似动作顶替。未经过专业动作审核。

来源：Shlomy Reshef 的 [Desk Break 固定提交](https://github.com/shlomorsh/desk-break/tree/8d475aa476b2c0e9ec6d09d8558faf17161e19ef)，MIT。源文件校验值在 `public/motion/source.json`；完整许可及第三方声明在 `public/licenses/`。本站做灰色材质、固定视角、支撑椅和离线视频，不修改动作姿势与节奏。手机不加载全库 GLB。

## 第二条路径：营养溯源

饮食 → 食品营养 → 搜索“鸡蛋” → 区分生全蛋和水煮全蛋 → 查看来源、版本和逐项字段 → 输入克数 → 选择日期/餐次/称量方式 → 保存 → 饮食日记 → 更正 → 我的/全部功能 → 进度与复盘 → 点击营养总量 → 原餐次 → 食品历史版本。

已接入 **7,793 个 USDA FoodData Central SR Legacy 2018-04 历史条目**，46,112 个现有基础营养字段，646 个缺失位置保持为空。六项为热量、蛋白质、脂肪、碳水、膳食纤维、钠。食品库索引和来源分片按需读取，不加入首页脚本或个人存储。

全库提供中文显示名称，并保留英文原名及来源。原有 80 条中文映射保持不变；新增译名按本项目术语表与上下文规则组合，**不是 USDA 官方中文名，也未经过逐条专业审核**。当前 5,080 条为中文直译、2,633 条带具体待核对说明；未确定对应的专名保留英文和中文类别，品牌保留原名。支持中文、英文、FDC 编号搜索。译名版本独立于营养版本，不改营养值或历史记录快照。

这是美国历史资料，含历史品牌和餐馆食品，**并非中国完整食品库，也不代表当前品牌配方**。来源为 USDA（CC0 / public domain），保留原始编号、名称、发布日期、计量单位、CSV 行、推导方式、数据版本和许可。零、缺失和来源估算分开；来源报告值不等于本项目实测。

`public/data/food-evidence.json` 保留原有 80 条的证据；完整库的来源、固定源包 SHA256、字段定义和分片校验在 `public/data/sr-legacy/manifest.json`。以官方固定包重建：

```powershell
python scripts/build-food-catalog.py --archive '..\data-source\usda-sr-legacy-2018.zip'
python scripts/build-full-food-library.py
python scripts/build-food-names.py
```

完整库脚本校验固定源包、食品编号和营养单位，并核对原有 80 条数值没有变化。中文名称脚本使用 `scripts/food-name-terms.tsv`，输出 `names-zh.json`，记录原文、术语、疑点、译名版本及索引/术语表校验值；没有外部翻译服务。源包下载地址在 manifest 中；源包位于仓库外，不随源码上传。24 个自编菜谱使用已有可核对原料，区分生重与熟重；营养按原料加总，未实测烹调损耗、残油或成品含水变化，不是外部标准菜肴或专业食谱。

找不到食品 → 保存待核对的原始文字与实际份量（不猜营养）→ 查找对应食品/菜谱 → 明确确认匹配与份量 → 保存营养快照。待核对记录保存在个人档案与备份里；首页、日记、复盘及溯源提示尚未纳入统计的摄入。补全后仅入账一次，保留原文字，可复用已有记录更正、删除与恢复。旧餐不依赖当前食品库加载，保存时的来源版本不会被新数据覆盖。

## 个人试用与边界

我的 → 创建个人档案，填写身高、目标与记录方式；体重、围度从身体页录入、更正并看趋势。报告保存原件；指标需人工填原文、位置、比较符号、单位和参考范围。没有 OCR 或医学解读。

我的 → 导出备份：包含当前档案及报告原件。导入校验结构/版本，始终新增档案，不覆盖已有档案。v1 升级 v2 前保留原始存储，不能靠清空数据升级。家庭页可选本次实际制作的菜，为明确选定的本机档案分份代记；所有参与档案共用该制作的可记录份量，报告和对话不在此页分享；同设备档案不是安全账户隔离。隐私四项分开：本地保存启用；同步未接入；云 AI 关闭；分享需明确选择。

AI 当前是本地规则与程序计算，支持食品候选、上下文卡片、草稿、记录汇总和旧汇总过期提示。**真实语言模型、后端凭据、跨账号权限、云同步均未接入**；个人档案不使用 10/20/30 分钟演示规则自动改计划。原有自动微调、暂停、旧确认失效和撤销逻辑仅在示例档案可体验，不能冒充个体化健康算法。没有开通或调用任何收费模型。

参考交互：[Nike Training Club 官方介绍](https://apps.apple.com/us/app/nike-training-club/id301521403)、[Hevy 组间休息](https://www.hevyapp.com/features/workout-rest-timer/)。借鉴准备/跟练/休息与统一核对，不搬用这些产品素材。

## 2026-11-12 审查后四项收口

1. 记录和执行一致性：日期在午夜、返回前台和操作时刷新；用户选定的补记日期和已开始训练的日期保留。日记进入记餐会显示日期/餐次，保存或离开后清除上下文。新增、更正、删除、恢复及撤销饮食后，受影响日期需要重新确认完整度。计划、今日、运动使用一致的完成/跳过状态；饮食安排完成不表示已摄入。计划动作详情返回原安排，不新建训练，也不被另一暂停中的训练劫走。
2. 报告管理：身体 → 测量与指标可更正、撤销、删除和恢复指标。报告 → 删除报告需二次确认，删除原件及关联指标/历史。删除请求先保存，再清除 IndexedDB 原件；中断或失败在报告页重试，未完成时禁止导出备份。此前导出的备份不会被远程清理。
3. 食品查询：助手和食品页复用完整索引、中文/英文/FDC 检索和来源分片。助手只作字面资料检索，最多 8 项，不是语义识别或自动记餐。结果保存名称/编号/版本，刷新后仍可打开。有疑点的条目显示“名称待核对”，具体疑点与原文可在详情查看。所有食品数值、源文件和译名表未改。
4. 家庭制作：菜谱 → 开始做菜 → 保存制作 → 为家人记录。份量按本次制作快照分配，跨档案共同扣减；更正、删除、恢复均重算可记录份量。单人备份仅保存他人已分配份数，不导出他人的日记；恢复生成独立制作编号，保留外部分配扣减，避免与原家庭重复统计。未记录份量不代表食物库存。

本轮复用既有控件、食品快照、计算、记录历史、IndexedDB 和备份结构，没有新增依赖。实际 UI 仍是响应式 Web，本地规则助手；无真实模型、OCR、云同步或安全账户隔离。详细验证以本轮 QA 文件为准，旧验收记录不代表本轮再次完成。
